# Contributing

Thank you for helping improve the OneTrace.pro libraries and plugins! Bug reports, fixes, docs and ideas are all welcome.

## Issues

- Search the existing issues first.
- For a bug, include the version of the library or plugin, the PHP and platform versions (Laravel, WordPress and WooCommerce, Magento), what you did, what you expected and what happened instead.
- Never post API keys, customer data or other personal data. Replace them with placeholders such as `cdp_sk_…`.
- Problems with your OneTrace.pro account or project belong to [support@onetrace.pro](mailto:support@onetrace.pro), and security issues to the [security policy](SECURITY.md).

## Pull requests

1. For anything bigger than a small fix, open an issue first so we can agree on the approach.
2. Keep each pull request focused on one change and add tests for it.
3. Run the checks described in the **Development** section of the repository's README — static analysis and tests must pass, the same as in CI.
4. Update the README when users would notice the change; describe it in the pull request so it lands in `CHANGELOG.md` with the next release.
5. Keep the supported versions: each README lists the PHP and platform versions the code must keep working on.

By submitting a pull request you agree that your contribution is licensed under the license of that repository.

## Code of conduct

Everyone taking part is expected to follow our [code of conduct](CODE_OF_CONDUCT.md).
